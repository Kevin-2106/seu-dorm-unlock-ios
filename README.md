# 门钥 · DoorKey for iOS

「住理生活」门锁系统的**非官方 iOS 客户端**：用**你自己的账号**登录，换取**你自己绑定的门锁**的开门凭据，通过**蓝牙 / NFC** 开门，并提供锁屏小组件、锁屏控制和快捷指令入口。

> 与武汉辛纳电子科技、「住理生活」官方 App 没有任何关联，也不使用其名称、图标或素材。

## 特性

### 开门
- **蓝牙开门**：连接 → 发送凭据 → 开锁，全流程自动完成。第一次成功后缓存外设 UUID，之后直连、跳过广播扫描；直连失败自动回退扫描。
- **NFC 碰锁开门**：打开 App 即进入持续监听，贴近门锁感应区直接开门，开完自动继续监听。
- **密钥轮换**：NFC 每次开门锁会返回新钥匙，自动保存。
- **凭据自动刷新**（离线次数用完 / 凭据过期时从服务器重取并重试）。⚠️ 见下方"验证状态"。

### 入口
- **锁屏 / 主屏小组件**：锁屏圆形、矩形、行内三种，外加主屏小号；点按后唤起 App 并**自动开始蓝牙开门**。
- **锁屏控制**（iOS 18+）：可替换锁屏左下 / 右下角的按钮。
- **快捷指令「开门」动作**：加在 App 本体里，**不依赖小组件扩展**。可放到锁屏的快捷指令控件、Action 按钮、轻点背面，或对 Siri 说"用门钥开门"。

### 凭据管理
- 手机号 + 密码登录，自动拉取设备号、凭据等参数。
- **配置码**：把已拉取的开门凭据（**不含账号密码**）导出成一段文本，在另一台登录同账号的设备上粘贴导入，免去每台设备都登录一次。
- 密码存 Keychain。

### 体验
- 首页只留开门这一件事，其余（登录、参数、日志）在设置页。
- **iOS 26 Liquid Glass** 适配，低版本自动退回常规材质；按钮样式可选玻璃实心 / 玻璃透明 / 实色 / 描边透明。
- 开门过程有视觉反馈：待机呼吸与陀螺仪视差，开门中背景变暗、bloom 与 RGB 分离的"蓄力"效果和从圆环射出的跃迁粒子，成功闪绿、失败闪红并抖动。
- **CoreHaptics 触感**（iPhone 8+）：搜索时持续细腻嗡鸣并渐强，成功是类似支付成功的双击，失败是两下强抖。
- 自定义首页背景图；几乎所有视觉 / 触感参数都在设置页「视觉与震动调节」里可调（含试震按钮、恢复默认）。
- 首页底部和设置页「关于」显示版本号、构建号、commit，并检测小组件扩展是否真的被装进来（侧载经常"以为装了其实没装上"）。

## 与 Android 版（上游）的对照

### 协议层：移植

加密（CRC8、RC4、设备密钥派生）、BLE 帧（`0x74`/`0x75`/`0x78`/`0x76`/`0x77`）、NFC 帧（`0xB1`）、错误码处理都是对上游 Kotlin 实现的移植。协议细节见上游的 [README-NFC.md](https://github.com/Haa1024/SEU-Door-Unlock/blob/main/README-NFC.md)。

移植时用独立的 Kotlin 与 Swift 工具链各跑一遍同样的输入，生成测试向量，**字节级比对一致**。

### 没有移植的

| 上游功能 | 这里的情况 |
|---|---|
| 支付宝一键登录 | ❌ 只有手机号 + 密码 |
| NFC 磁贴写卡 / 碰磁贴触发 BLE 开门 | ❌ |
| 读 NDEF / 用标签 UID 反推设备号（诊断用途） | ❌ |
| 旧的"在线重置离线计数器"方案（上游已标注废弃） | ❌ |
| 占用官方包名的变体及相关说明 | ❌ 不涉及 |
| 手动填写 MAC 地址直连 | ⚠️ iOS 拿不到真实 MAC，改用外设 UUID 缓存 |

### iOS 上做不到、或和 Android 不同的（平台限制，不是 bug）

- **碰一下锁就自动打开 App：做不到。** 上游靠 Android 的后台 NFC 分发（门锁标签里指名了官方包名，系统把标签直接交给它）。iOS 没有对应机制：
  - 读取这种标签需要的是原始帧收发（`NFCMiFareTag.sendMiFareCommand`），这只能在 App **前台**的读卡会话里做，并且每次都会弹出系统的"准备扫描"面板；
  - iOS 的后台标签读取只在 iPhone XS 及以上可用，且只处理标准 NDEF 内容，由系统根据内容决定打开哪个 App——对这把锁来说，那是官方 App 的域名，第三方无法抢占。
  - 所以使用方式是：打开 App（或点小组件 / 快捷指令）→ 然后贴锁。
- **没有后台蓝牙**：只在前台工作，锁屏小组件的作用是"唤起 App 再开门"，不是在小组件进程里直接开。
- **小组件是纯静态的**：不读 App 数据（不显示设备号等），也不使用 App Group——SideStore 对免费账号会改写 App Group ID，容易出问题。
- **读卡每次都有系统面板**：Android 可以无界面读卡。
- **蓝牙 MTU 等底层参数不可控**：CoreBluetooth 不暴露。

### NFC 为什么侧载通常用不了，越狱 / TrollStore 却可以

这是实测过的现象，也是整个项目里最容易让人困惑的一点。

**原因：** 使用 CoreNFC 读取非 NDEF 标签，App 的签名里必须带有 `com.apple.developer.nfc.readersession.formats` 这个 entitlement。iOS 默认要求 entitlement 必须由**苹果签发的 provisioning profile** 授权，而苹果只允许**付费开发者账号**（$99/年）在 App ID 上开启 "NFC Tag Reading" 这项能力。

- **SideStore / AltStore / Sideloadly 等侧载工具**：用你的免费 Apple ID 向苹果申请 profile，申请不到 NFC 能力，装上去的 App 签名里就没有这个 entitlement。结果是 `NFCTagReaderSession.readingAvailable` 为 `false`，App 里显示"不支持 NFC 读卡"。
- **TrollStore**：利用 CoreTrust 的签名校验漏洞，让系统把"任意伪造的签名"当作有效。此时 entitlement 直接取自二进制自带的签名，**不再需要苹果签发的 profile 来授权**，想声明什么就是什么，所以 NFC 能用。代价是依赖特定的 iOS 版本区间，以 TrollStore 官方说明为准。
- **越狱**：越狱通常会放宽或补丁 AMFI 的校验，用伪签名（如 `ldid -S`）嵌入 entitlement 即可，原理同上。
- **LiveContainer**：被"寄生"的 App 运行在宿主 LiveContainer 的进程里，只能使用宿主自己签名里的 entitlement，同样没有 NFC。

| 安装方式 | 蓝牙 | NFC | 说明 |
|---|---|---|---|
| TrollStore | ✅ | ✅ | iPhone 7（iOS 15）实测 NFC 可用 |
| 越狱 + 伪签名 | ✅ | ✅（原理上） | 未单独测试 |
| 付费开发者账号（Xcode / SideStore 等） | ✅ | ✅（原理上） | 需在 App ID 上开启 NFC Tag Reading，未测试 |
| SideStore / AltStore / Sideloadly + 免费 Apple ID | ✅ | ❌ | 实测：显示"暂不支持 NFC 读卡" |
| LiveContainer | ✅ | ❌ | 实测：同上 |

**蓝牙不受这个限制**——它只需要 Info.plist 里的用途说明，不需要特殊 entitlement，所以任何方式装上都能开门。

### 免费 Apple ID 侧载的其他限制

- **App ID 配额：滚动 7 天内最多 10 个。** 小组件扩展要多占 1 个（`.widget`）。额度满时，侧载工具会让你"移除 app extension"，装上去的就没有小组件 / 锁屏控制——这时用快捷指令那条路。删除 App 不会释放 App ID，要等它自然过期。
- **签名 7 天过期**，需要定期刷新（SideStore 可自动刷新）。
- 小组件扩展的最低系统版本是 iOS 16，锁屏控制是 iOS 18；主 App 最低 iOS 15，所以 iPhone 7 上没有小组件，但 App 本体可用。

## 验证状态

下面如实写出哪些在真机上跑过、哪些没有：

| 项目 | 状态 |
|---|---|
| 蓝牙开门、登录、拉取凭据 | ✅ 真机验证 |
| NFC 开门 | ✅ 真机验证（iPhone 7 + TrollStore） |
| 视觉、触感效果 | ✅ 在真机上看过并按反馈调整多轮；参数可在设置页继续调 |
| 凭据自动刷新（锁返回 `25` / `24` / `27` 时的恢复流程） | ⚠️ 逻辑已移植、可编译，**没有在真机上触发过** |
| NFC 路径的自动刷新 | ❌ 上游也没有；NFC 失败只会提示 |
| 配置码导出 / 导入 | ⚠️ 未确认 |
| 锁屏小组件、锁屏控制 | ⚠️ 未在真机验证（作者的账号 App ID 额度已满，扩展被移除） |
| 快捷指令「开门」动作 | ⚠️ 未验证 |

**关于配置码的一个推断（未验证）**：NFC 每次开门锁都会换新的 chainKey，旧的随之失效。如果两台设备共用同一份配置码，其中一台用 NFC 开过门后，另一台手里的可能就是旧钥匙，需要登录一次重新拉取。所以配置码更适合"备用 / 偶尔用"的设备。

## 使用

1. 设置页输入手机号与密码 →「登录并拉取门锁凭证」。⚠️ 这会把官方 App 的登录会话顶下线（服务端单点登录的行为）。
2. 回首页点「开门」；或者 App 在前台时直接把手机贴近门锁感应区（NFC）。
3. 其他设备：在已配置的设备「导出配置码」→ 新设备「从剪贴板导入」。
4. 想放到锁屏：添加锁屏小组件 / 控制；或在"快捷指令"里添加「开门」动作。

## 构建

不需要本地 Xcode。GitHub Actions 的 macOS runner 构建（`.github/workflows/ios.yml`，仅手动触发）：

- [XcodeGen](https://github.com/yonaskolb/XcodeGen) 根据 `ios/DoorUnlock/project.yml` 生成工程；
- 构建期不签名（xcodebuild 在新 SDK 上不允许构建期 ad-hoc 签名），随后用 `codesign -s -` 由内向外做 ad-hoc 签名：先签小组件扩展，再签主 App 并嵌入 NFC entitlement；
- 产物是 ad-hoc 签名的 `.ipa`，交给 TrollStore / SideStore 等自行安装；
- 构建号 = Actions 运行编号，commit 短哈希会写进 Info.plist，在 App 里显示。

目前还没有 App 图标，所以仓库不发布构建产物。
